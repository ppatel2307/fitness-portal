## Overview

Two deployment targets:
- **API + DB:** Render, configured via `render.yaml` (Docker for API, managed PostgreSQL)
- **Frontend:** Vercel, Vite build output

## Pre-Deploy Checklist (always run first)

```bash
npm run build          # both apps must compile clean
npm run lint           # fix any linting errors
```

Then manually verify:
- [ ] Login flow works (email + Google OAuth)
- [ ] At least one client role flow (dashboard → workouts → AI chat)
- [ ] Admin dashboard loads

## API — Render

Infrastructure is declared in `render.yaml`. Render auto-deploys on push to the connected branch.

**Required env vars (set in Render dashboard, not in render.yaml):**

| Var | Source |
|-----|--------|
| `DATABASE_URL` | Auto-set from the linked DB |
| `JWT_ACCESS_SECRET` | Auto-generated by Render |
| `JWT_REFRESH_SECRET` | Auto-generated by Render |
| `GOOGLE_CLIENT_ID` | Google Cloud Console |
| `GOOGLE_CLIENT_SECRET` | Google Cloud Console |
| `GEMINI_API_KEY` | Google AI Studio |
| `ADMIN_EMAIL` | Your email |
| `ADMIN_PASSWORD` | Set at first deploy |
| `STRIPE_SECRET_KEY` | Stripe Dashboard |
| `STRIPE_WEBHOOK_SECRET` | Stripe Dashboard → Webhook endpoint |
| `FRONTEND_URL` | Your Vercel URL (set after first frontend deploy) |

**Stripe webhook URL:** `https://<render-service>.onrender.com/api/stripe/webhook`
Register this in the Stripe Dashboard under Webhooks. Update `STRIPE_WEBHOOK_SECRET` with the signing secret Stripe provides.

**DB migrations on deploy:**
Render runs `npm run postinstall` (which runs `prisma generate`). For migrations, trigger manually via Render Shell:
```bash
npm run db:migrate:prod -w apps/api
```
Or add it to a pre-deploy command in `render.yaml`.

## Frontend — Vercel

Build command: `npm run build -w apps/web`
Output dir: `apps/web/dist`

**Required env vars (set in Vercel dashboard):**

| Var | Value |
|-----|-------|
| `VITE_API_URL` | `https://<render-service>.onrender.com` |

After first Vercel deploy:
1. Copy the Vercel URL
2. Set `FRONTEND_URL` in Render to that URL (fixes CORS)
3. Redeploy API (or it takes effect on next deploy)

## Rollback

**API:** In Render dashboard → Deploys → select a previous deploy → Rollback.
**Frontend:** In Vercel dashboard → Deployments → Promote a previous deployment.
**DB:** There is no automated rollback. Write a down migration manually if needed (`prisma migrate resolve`).

## Health Check

API health endpoint: `GET /health` — returns `{ status: 'ok' }`. Render pings this to determine service health.
